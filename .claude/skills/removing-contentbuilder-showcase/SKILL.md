# Removing the content row showcase

The showcase consists of:

| Piece | What | Removed by |
|---|---|---|
| Pages | `gridbuilder` page + its column type and combination pages (section `pages`) | `ddev craft statik/contentbuilder-cleanup` |
| Images | Asset folder `contentbuilder-showcase/` in Public Files | `… --with-images` |
| Template code | Marked blocks in `templates/_site/_snippet/_content/_contentBuilder.twig` | This skill, step 2 |
| Feature code (optional) | Commands, helper, Twig variable, config, content, skills | This skill, step 4 — only when asked |

Default scope: **steps 1–3** (pages + template). Ask whether the imported images should go too if the user didn't say. Only do step 4 when the user wants the showcase feature gone from the project (not just cleaned up for now) — after step 4 it can't be regenerated.

## 1. Remove the pages

```bash
ddev craft statik/contentbuilder-cleanup --interactive=0                  # pages → trash
ddev craft statik/contentbuilder-cleanup --interactive=0 --with-images    # …and the image folder
ddev craft statik/contentbuilder-cleanup --interactive=0 --hard-delete    # permanently instead of trash
```

This removes pages in the database of the environment it runs in (usually local DDEV). On staging/production it has to be run there too (e.g. `php craft statik/contentbuilder-cleanup` over SSH) — tell the user rather than doing it yourself.

## 2. Remove the showcase code from `_contentBuilder.twig`

All showcase code sits between `{# contentbuilder-showcase:start … #}` and `{# contentbuilder-showcase:end #}` markers. Remove **every** marked block, including the marker comments:

1. Before the `for` loop: `isShowcase`, `showcasePageWidth` and `showcaseWidthClass`.
2. At the top of the loop: `variationAttr` and the HTML comment `<!-- Contentbuilder variation: "#1 · …" -->` it writes on showcase pages.
3. Two inline blocks around the `include` of the block template: the `lg:w-2/3` / `lg:w-3/4` wrapper of the "Gridbuilder – 2/3 page" and "3/4 page" showcases. Keep the `include` line itself:

```twig
			{# contentbuilder-showcase:start #}{% if showcaseWidthClass %}<div class="{{ showcaseWidthClass }} @container">{% endif %}{# contentbuilder-showcase:end #}
			{% include '_site/_snippet/_content/_blocks/_'~block.type.handle with { settings: settings} %}
			{# contentbuilder-showcase:start #}{% if showcaseWidthClass %}</div>{% endif %}{# contentbuilder-showcase:end #}
```
becomes
```twig
			{% include '_site/_snippet/_content/_blocks/_'~block.type.handle with { settings: settings} %}
```

Don't leave empty lines behind where the blocks were (one blank line between sections, as in the rest of the file). Everything else in the file (the row background and "Spacing above" logic, `settings`, `field`) is the content builder itself: keep it.

**The project may have changed this file since** (extra settings, wrappers, attributes). Remove only the showcase parts and keep everything else. If the markers are missing (someone reformatted the file), find the showcase code by its names: `isShowcase`, `isContentbuilderShowcasePage`, `variationAttr`, `contentbuilderShowcaseLabel`, `showcasePageWidth`, `showcaseWidthClass`, `Contentbuilder variation`.

Also check other templates for copies (e.g. a second site's content builder):
```bash
grep -rn "contentbuilder-showcase\|isShowcase\|variationAttr\|contentbuilderShowcase\|showcaseWidthClass\|Contentbuilder variation" templates/
```

## 3. Verify

1. The grep above returns nothing.
2. Clear the template caches (the page template uses `{% cache %}`): `ddev craft clear-caches/all`.
3. A page with Content Builder content still renders: `curl -sk -o /dev/null -w '%{http_code}' https://<project>.local.statik.be/nl/<a-content-page>/` → `200`, and its HTML has no `Contentbuilder variation` comment.
4. `https://<project>.local.statik.be/nl/gridbuilder/` → `404` (if the pages were removed).
5. Show the user the `git diff` of the template.

## 4. Optional: remove the feature entirely

Only when asked. After this, the showcase can't be regenerated. Remove:

- `modules/statik/src/console/controllers/ContentbuilderController.php` (generator)
- `modules/statik/src/console/controllers/ContentbuilderCleanupController.php` — **run step 1 first**, it's the cleanup command
- `modules/statik/src/helpers/ContentbuilderShowcase.php`
- The `contentbuilderShowcaseLabel()`, `isContentbuilderShowcasePage()` and `showcasePageWidth()` methods in `modules/statik/src/variables/StatikVariable.php` (and their `use` lines; keep the class)
- The two Trinity page width listeners in `modules/statik/src/Statik.php` (`Rows::EVENT_DEFINE_PAGE_WIDTH` and `Rows::EVENT_REGISTER_PAGE_WIDTHS`, under the `contentbuilder-showcase` comment) and their `use` lines — keep the Trinity plugin and `config/trinity.php`, they're the content row block itself
- `gridbuilderShowcaseSlug` and its comment in `config/custom.php`
- `config/contentbuilder-showcase/` (content.json + images)
- `.claude/skills/updating-contentbuilder-showcase/`, the "Showcase" lines in `.claude/skills/understanding-project-architecture/SKILL.md`, and this skill last

Then check nothing references it any more and PHP still loads:
```bash
grep -rn "ContentbuilderShowcase\|contentbuilderShowcase\|contentbuilder-showcase\|statik/contentbuilder" modules config templates .claude
ddev craft help statik   # must run without errors
```
