# Updating the Content Builder showcase

`ddev craft statik/contentbuilder` builds a page per Content Builder block (under the page with slug `contentbuilder`, set in `config/custom.php` → `contentbuilderShowcaseSlug`), with one instance of the block for every combination of its variable fields. Each instance's variation is described in a `data-contentbuilder-variation` attribute on its section wrapper (e.g. `#3 · Image position: right · Background Color: section--light`). It is not rendered, so the page looks exactly like real output; inspect it in devtools or select it in tests.

**All content comes from one file: `config/contentbuilder-showcase/content.json`.** Your job is almost always to edit that file and rerun the command — not the PHP.

| Piece | Path |
|---|---|
| Content (edit this) | `config/contentbuilder-showcase/content.json` |
| Local images (optional) | `config/contentbuilder-showcase/images/` |
| Command | `modules/statik/src/console/controllers/ContentbuilderController.php` |
| Which fields vary + labels | `modules/statik/src/helpers/ContentbuilderShowcase.php` |
| Variation attribute in the frontend | `templates/_site/_snippet/_content/_contentBuilder.twig` (`isShowcase`) |

## Workflow

1. **Inspect the current blocks** — always first, blocks change over time:
   ```bash
   ddev craft statik/contentbuilder --dry-run
   ```
   Per block this prints the number of instances, the dimensions (`field[value|value]`), and `placeholder content` for fields that have no content in content.json (they get lorem ipsum / a generic fallback). A red line means the block exceeds `--max` (150) and will be skipped.
2. **Gather content** — scrape (below) or invent (below).
3. **Edit `content.json`** following the format below. Keep field handles exactly as the dry run prints them.
4. **Validate & generate**:
   ```bash
   ddev craft statik/contentbuilder --dry-run   # no placeholder / warning lines left that you meant to fill
   ddev craft statik/contentbuilder             # or --block=quote,faq for just a few blocks
   ```
   Fix every `!` warning (unknown image key, missing entry URI, disabled link type, …) and rerun.
5. **Check the result** in the browser (`https://<project>.local.statik.be/nl/contentbuilder/`) — the parent page links to all block pages. With Playwright, take a screenshot of one or two block pages; to tell instances apart, read `[...document.querySelectorAll('[data-contentbuilder-variation]')].map(el => el.dataset.contentbuilderVariation)`. Mention the page URL to the user.

Changed images? Rerun with `--refresh-images` (files are otherwise reused by filename). New image keys are imported automatically.

## content.json format

```jsonc
{
  "meta":   { "theme": "…", "source": "https://scraped-site.be or null", "language": "nl", "updated": "YYYY-MM-DD" },
  "parent": { "title": "Contentbuilder", "intro": "<p>Shown in the header of the overview page</p>" },
  "assets": { "volume": "publicFiles", "folder": "contentbuilder-showcase" },

  // Image pool, referenced by key from Assets fields
  "images": {
    "hero": { "url": "https://…/photo.jpg", "alt": "…", "caption": "…", "copyright": "…" },
    "team": { "file": "images/team.jpg", "alt": "…", "filename": "team.jpg" }   // file = relative to content.json
  },

  // Samples used to show off CKEditor features (see "Rich text" below); all keys optional
  "richText": {
    "link": "https://www.thekindkids.be",          // href for sample links — always this URL
    "bold": "bold text", "italic": "italic text", "linkText": "a link",   // used only when a text lacks them
    "headings": ["…", "…", "…"],                    // one per allowed heading level, cycled
    "listItems": ["…", "<strong>…</strong> …", "…"], // items for the <ul> and the <ol>
    "paragraph": "<p>…</p>"                         // after headings once the lists are used up
  },

  // Excessively long title for the long-title stress example (see below)
  "longTitle": "An excessively long title … including an unbreakable Supercalifragilistic…word",

  // Shared content per FIELD HANDLE — used by every block that has that field
  "fields": {
    "blockTitle": "Plain string",
    "text": "<p>HTML for CKEditor fields</p>",
    "image": ["hero"],                       // Assets: list of image keys, or "*" for all images
    "cta": [ { "type": "url", "value": "https://…", "text": "Read more",
               "newWindow": false, "fields": { "ctaFieldLinkLayouts": "btn btn--primary" } } ],
    "video": "https://www.youtube.com/watch?v=…",  // Url fields: a string
    "entries": "@showcase"                   // Entries: "@showcase" (the showcase pages) or a list of URIs ["news/my-article"]
  },

  // Per BLOCK HANDLE overrides (win over "fields")
  "blocks": {
    "quote": {
      "fields": { "text": "…", "writer": "…" },
      "fixed":  { "backgroundColor": "section--default", "cta": false },  // pin dimensions (see below)
      "skip":   false                                                      // true = no page for this block
    },
    "faq": { "fields": { "faqBlock": [ { "blockTitle": "Question?", "text": "<p>Answer</p>" } ] } },  // nested Matrix: list of items keyed by field handle, optional "type"
    "form": { "fields": { "form": "contact_NL" } }                         // Formie form handle; null = first form
  }
}
```

Value rules per field type:
- **CKEditor**: see "Rich text" below.
- **Plain text / Title (Anchor)**: plain string, no HTML.
- **Hyper (cta…)**: list of links. `type` = `url` | `email` | `entry` (value = entry URI, `__home__` for home) | `asset` (value = image key). `fields.ctaFieldLinkLayouts` = a key from `config/config-values-field.php` → `CTA styles` (`btn btn--primary`, `btn btn--secondary btn--ext`, `link link--ext`, …).
- **Embed** (plain text): full embed HTML; the template only renders it if it contains `src="https:`.
- **Option fields** (Position, Width, Background Color, lightswitches) are **not** content — they are the combinations. Don't put them in `fields`; pin them with `fixed` instead.
- `null` means "no content here → fallback". To force a field empty, pin it in `fixed` with `false`.

### Rich text (CKEditor fields)
The command reads each CKEditor field's `toolbar` and `headingLevels` at runtime (`config/project/fields/ckEditor*.yaml`) and makes sure the showcase exercises them:
- **Every instance** contains **bold**, *italic* and linked text (when the toolbar has them). Write the content.json text that way: 1–3 short `<p>` paragraphs where some words are `<strong>`, some `<em>` and some are `<a href="https://www.thekindkids.be">…</a>` — **always link to https://www.thekindkids.be**, also when scraping (keep the scraped link text, replace the href). If a text lacks one, the command appends a sample sentence and warns.
- **One instance per field** (the first where the field is filled; for nested FAQ items, the first item) additionally gets a heading for every allowed level plus a `<ul>` and an `<ol>`, built from `richText`. So **don't put headings or lists in the regular texts** — they would appear in every instance.
- Only use tags the field's editor allows; the command warns about others (`<h3>` in the FAQ answer field "without H3", lists in the table field, …). Tables go only in the table field, as `<figure class="table"><table>…</table></figure>`. No inline styles or classes; never `<h1>`/`<h2>` (block titles render as `<h2>`).
- Write `richText.headings`, `listItems` and `paragraph` in the showcase language and theme too.

### Long titles
Every title field — Title (Anchor) fields (`blockTitle`, `titleColumn1/2`, FAQ questions) and plain text fields with "title" in their handle — gets `longTitle` in **one instance per block**: the second instance where it is filled (the only one if there is just one). For nested FAQ items it's the first question of that instance. Its variation attribute says `Title (Anchor): long`. Keep `longTitle` over 100 characters (that is what marks it `long`), in the showcase language, and include one very long word **without hyphens** so overflow on small screens is actually tested.

### Reducing combinations (`fixed`)
Every optional field doubles the instances (filled/empty), every option field multiplies by its option count. When a block is too large or a variation is meaningless, pin it: `"fixed": { "backgroundColor": "section--default" }` (option value), `"fixed": { "videoCaption": true }` (always filled) or `false` (always empty). Only do this when the user asks for fewer variations or a block exceeds `--max` — by default the showcase shows **all** combinations.

## Scraping content from an existing website

Goal: content that represents the real site (tone, text length, real images), mapped onto our blocks.

1. Ask for (or use) the site URL. Fetch the homepage + 3–6 content-rich pages (about, services, an article, FAQ, contact). Use `WebFetch` for text; use Playwright (`browser_navigate` + `browser_evaluate`) when content is JS-rendered or to collect image URLs (`[...document.images].map(i => ({src: i.currentSrc || i.src, alt: i.alt, w: i.naturalWidth}))`).
2. Map what you find, per block from the dry run:
   - headings → `blockTitle`, `titleColumn1/2`; paragraphs/lists → `text`, `textColumn1/2` (keep realistic length: 1–3 short paragraphs, sometimes a list);
   - buttons/links → `cta` (real link texts, absolute URLs to the scraped site);
   - testimonials → `quote.text` / `writer`; FAQ sections → `faqBlock`; tables (prices, opening hours) → `customTable.table`;
   - YouTube/Vimeo links on the site → `video`; maps/iframes → `embed`.
3. Images: pick 4–6 large photos (≥1200px wide, landscape; one square portrait for `authorImage`). Prefer downloading them into `config/contentbuilder-showcase/images/` (`curl -L -o …`) and referencing them with `"file"` so the showcase keeps working when the source site changes; otherwise use `"url"`. Always write a meaningful `alt`. Skip logos, icons and tracking pixels.
4. Set `meta.source`, `meta.language`, `meta.updated`. Content is written to **all sites** (nl/fr/en) identically, so use the site's main language unless the user says otherwise.
5. The scraped content is for internal/demo use on the showcase; don't copy personal data (names/photos of private people in testimonials) — replace author names with a plausible fictional one if unsure.

## Inventing content for a theme

When there's no site ("make it for a zoo", "fitness brand"):
- Write in the requested language (default: the primary site language, `nl-BE`, unless told otherwise); consistent fictional organisation name and tone.
- Vary lengths realistically: short punchy titles (3–7 words), body text 40–120 words, CTA texts 1–3 words.
- Images: use themed stock images with stable URLs (e.g. `https://images.unsplash.com/photo-…?w=2400` from a search you actually did, or `https://picsum.photos/id/<id>/2400/1600.jpg`). Never invent URLs you haven't verified — check each with `curl -sI` (expect `200` and an `image/*` content type).
- Videos: real YouTube/Vimeo URLs that exist (verify).
- Set `meta.theme`.

## When blocks changed (new block, new field, removed block)

The command reads blocks and fields from Craft at runtime — **no PHP changes are needed** for new/changed blocks as long as their field types are known:
- New block → it gets a page automatically; add `blocks.<handle>.fields` for its content (the dry run lists its placeholder fields).
- Removed block → its page is deleted on the next full run.
- New/renamed field handle → add content under the new handle; remove the old key.

Only touch PHP when the dry run shows `No content for … (<Field type>)` for a field type that has no fallback, or a new kind of variant field should become a dimension:
- New variant field type (e.g. a new select-like plugin field) → `ContentbuilderShowcase::dimensionValues()`.
- New content field type (how a content.json value becomes a field value) → `normalizeContent()` / `fallbackValue()` / `emptyValue()` in the controller.
